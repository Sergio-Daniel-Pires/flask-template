# [[ project_name ]]

A lean Flask + React starter: one small app surface, a documented API, real
backend tests, and Playwright against the real Flask server.

The starter ships a single Home placeholder. If the task does not ask for a
landing/home page, remove or replace it. Echo/About/Notes pages are intentionally
not included; the echo endpoint remains as a small API example.

## Requirements

- Python 3.11+
- Node.js 20+ (22 recommended)
- [uv](https://docs.astral.sh/uv/) recommended; `pip` also works
- Docker only for production/deploy

## Quick start

Open two terminals. Create the environment once:

```bash
uv sync --extra dev
```

`uv sync` creates `uv.lock`; commit it with the project for reproducible installs.

Activation is optional with `uv run`, but useful for editors and direct commands.

Windows PowerShell:

```powershell
.\.venv\Scripts\Activate.ps1
# If script execution is blocked:
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
```

Linux/macOS:

```bash
source .venv/bin/activate
```

Backend:

```bash
uv run flask --app project.app run --debug
# or, with the venv activated:
flask --app project.app run --debug
```

Frontend, in the second terminal:

```bash
cd frontend
npm install
npm run dev
```

- Frontend: <http://localhost:5173>
- API: <http://localhost:5000>
- Swagger: <http://localhost:5000/api/docs>
- Health: <http://localhost:5000/healthz>

Without `uv`:

```bash
python -m venv .venv
# activate as above
pip install -e ".[dev]"
flask --app project.app run --debug
```

Stop the servers with `Ctrl+C`. If a port is stuck on Windows:

```powershell
Get-NetTCPConnection -LocalPort 5000,5173 -State Listen
Stop-Process -Id <PID> -Force
```

## Tests

```bash
uv run ruff check .
uv run ruff format --check .
uv run pytest

cd frontend
npm run typecheck
npm run build
npx playwright install --only-shell chromium   # first time
npm run test:e2e
```

`npm run test:e2e` builds the frontend, serves it through Flask on port 5050,
and exercises the **real backend**. `npm run test:e2e:guard` fails the suite if
an E2E test mocks `/api` with `page.route`, MSW, or `route.fulfill`. Mocking is
allowed only in unit/component tests outside `e2e/`.

`npm run test:e2e:dev` reuses running Flask + Vite servers for the fast loop.

The coverage matrix, including what is **not** covered (idempotency,
concurrency, auth), is in [`docs/testing.rst`](docs/testing.rst).

## Documentation

- **API only:** Swagger at `/api/docs` (run the backend first). Do not duplicate
  schemas elsewhere.
- **Implementation docs:** [`docs/`](docs/) in Sphinx `.rst` — architecture,
  development, testing, API, deployment (and database when enabled).
- **Security:** [`SECURITY.md`](SECURITY.md) with the baseline and accepted
  risks (ACK).
- **Agents:** [`AGENTS.md`](AGENTS.md) with the docs-first loop, test reporting,
  and E2E guardrails.

Build the Sphinx docs:

```bash
uv sync --extra docs
uv run sphinx-build -W -b html docs docs/_build/html
```

Open `docs/_build/html/index.html`.

## Deploy

The workflow [`.github/workflows/deploy.yml`](.github/workflows/deploy.yml)
already contains the host, user, path, and upstream port. Configure in GitHub:

- `VPS_SSH_KEY` (required): private SSH key
- `VPS_FINGERPRINT` (recommended): host fingerprint

On the VPS, run `bash deploy/setup-vps.sh` once. The container binds to
`127.0.0.1`; nginx/Caddy terminates TLS and applies rate limits. See
[`docs/deployment.rst`](docs/deployment.rst) for the full setup and operational
notes.

## Agent workflow

- `AGENTS.md` is the source of truth for scope, docs-first, tests, and reporting.
- UI direction: Taste only to explore two options; Impeccable to implement the
  chosen app screen.
- Security: `owasp-review` on the diff; accepted findings go to `SECURITY.md`.
- E2E must hit the real backend; the guard prevents a second mocked API.
